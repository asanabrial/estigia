section: The harness

- **The run's own merge commit can be tagged and fast-forwarded to, and `git -C <dir>` is read for every git delivery.** Issue #58. After a merge, `git tag -a <tag> -F <notes> <merge-sha>` — the command the delivery binding prescribes — and `git merge --ff-only origin/main` were refused `verdict-bound-to-other-bytes`, because the delivered commit is not the reviewed head. The commit a tag names (else the checkout's `HEAD`), or a fast-forward's target, is now also accepted when it is a two-parent merge whose second parent is the receipt's head and whose first parent descends from the receipt's base, the topology `match_own_close` applies, now held in `ReviewTransaction::delivered_by_merge` for both. A tag naming some other commit is refused even where the checkout sits at the reviewed head. A `cd <dir> &&` or `git -C <dir>` before `git tag` is now judged against `<dir>` and, when unreadable, refused `review-checkout-unreadable`, as for `git merge`. `docs/honesty.md` named the wrong code for that refusal and is corrected (`docs/honesty.md`).
